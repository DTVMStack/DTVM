# 项目原则

定义项目开发原则和约束，为所有后续开发活动提供指导原则。

## 用户输入

你输入的内容即为上下文。

## 执行步骤

### 1. 检查现有宪法文档

检查是否存在以下文件：
- `.specify/memory/constitution.md`
- `specs/constitution.md`
- `CONSTITUTION.md`

如果存在，读取现有内容并准备更新。

### 2. 收集项目上下文

分析项目以确定适当的约束：
- 编程语言和框架
- 目标平台和部署环境
- 性能要求
- 安全和合规要求
- 团队规模和协作模式

### 3. 生成宪法文档结构

创建或更新包含以下部分的宪法文档：

#### 项目愿景
- 项目目的和目标
- 目标用户/用例
- 成功定义

#### 技术约束
- 允许的编程语言
- 允许的框架和库
- 架构模式要求
- 平台要求

#### 质量标准
- 代码风格指南
- 测试覆盖率要求
- 文档标准
- 性能基准

#### 开发流程
- Git 工作流
- 代码审查要求
- CI/CD 要求
- 发布流程

#### 安全和合规
- 数据保护要求
- 访问控制标准
- 审计要求
- 法律合规考虑

#### 团队协作
- 沟通协议
- 决策制定流程
- 争议解决
- 知识共享

### 4. 写入文档

将宪法文档写入 `.specify/memory/constitution.md`。

### 5. 验证

确认文档包含：
- 所有必需的部分
- 清晰、可执行的约束
- 与项目目标一致
- 团队共识（如果适用）

### 6. 报告

报告宪法文档的位置和任何需要人工审查的关键决策。
