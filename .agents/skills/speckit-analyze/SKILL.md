# 项目分析

分析项目一致性，检查规格、设计和实现之间的一致性和完整性。

## 用户输入

你输入的内容即为上下文。

## 执行步骤

### 1. 收集项目工件

识别并收集所有相关项目工件：
- 功能规格（`specs/features/*/spec.md`）
- 模块规格（`specs/modules/*/spec.md`）
- 设计文档（`research.md`, `data-model.md`, `plan.md`）
- 任务列表（`tasks.md`）
- 实现代码

### 2. 分析一致性

检查以下一致性方面：

#### 规格到设计
- 功能规格中的所有需求都在设计中有对应
- 数据模型与规格中定义的实体匹配
- API 合约与User Story一致

#### 设计到任务
- 设计中的所有组件都有对应的实现任务
- 任务依赖关系与设计中的依赖关系一致
- 测试任务覆盖所有设计组件

#### 任务到实现
- 所有任务都已完成（或正确跟踪）
- 实现与任务描述匹配
- 文档与实现一致

#### SSOT 一致性
- 功能规格正确引用模块 SSOT
- 没有重复定义
- 更新正确传播到模块规格

### 3. 识别问题

标记以下类型的问题：
- 缺失的需求或功能
- 不一致的命名或术语
- 冲突的定义
- 孤立或未连接的组件
- 过时的文档

### 4. 生成报告

生成包含以下内容的分析报告：

#### 摘要
- 总体一致性评分
- 问题数量和严重程度

#### 详细发现
- 每个问题的描述
- 受影响的文件
- 建议的修复

#### 建议
- 优先修复的问题
- 改进建议

### 5. 输出报告

将报告写入：
- 控制台输出（摘要）
- 文件（详细报告）：`FEATURE_DIR/analysis/CONSISTENCY_REPORT.md`

### 6. 报告

报告分析结果，包括：
- 一致性评分
- 发现的问题数量
- 高优先级问题
- 建议的后续步骤
